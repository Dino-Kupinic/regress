title: Reports and mutation scores
description: What a run saves, how the mutation score is calculated, and how Regress decides which tests to keep.
---

Every run writes a directory under the project's `.regress/runs/`. The directory name is the run ID: a timestamp, then the source file's name lowercased, with characters other than letters and digits turned into hyphens, for example `20260926-230928-defu`. A second run for the same file in the same second gets a numeric suffix. `.regress/` contains a `.gitignore` that keeps all of it out of Git.

## Run directory

```text
.regress/runs/20260926-230928-defu/
├── report.json            # the report shown by `regress report` and the web app
├── events.jsonl           # progress log (API runs only)
├── tests/
│   ├── 0-baseline.test.ts   # the test file at each stage
│   ├── 1-generated.test.ts
│   └── 2-improved.test.ts
├── llm/
│   ├── 01-generated-attempt1.prompt.md
│   └── 01-generated-attempt1.response.json
├── vitest/
│   ├── baseline.json        # existing-test run
│   ├── baseline.log
│   ├── 01-generated-attempt1.json
│   └── 01-generated-attempt1.log
└── stryker/
    ├── mutation-1.json      # Stryker mutation reports
    ├── stryker-1.config.json
    └── stryker-1.log
```

Each model call saves its prompt and raw response under `llm/`, named by call number, stage, and attempt (`01-generated-attempt1`). Vitest writes `{name}.json` and `{name}.log` for that same name; the existing-test run is `baseline`. Stryker files are numbered from 1 in the order mutation runs happen, which is not the stage index: `mutation-1.json` is the first mutation run, whether that was the baseline or the generated tests. Tool logs keep the last 1 MiB of output. Test snapshots use the test file's suffix, so a `*.spec.ts` file is saved as `0-baseline.spec.ts` rather than `0-baseline.test.ts`.

While an API run is in progress its directory also holds `.api-recovery.json`, the record used to restore the source and test files if the server is killed. It is removed when the run ends. Leave it in place after a crash; see [recovery](/docs/deployment/application#recovery-after-interruption).

Read a report with:

```bash
regress report                 # the latest run
regress report --list          # all runs
regress report 20260926-230928-defu --mutants 25
regress report defu --json     # raw report.json
```

The web app shows the same data on each run's page, and serves every file on the **Overview** tab's artifact list.

## Stages

A run records one stage per version of the test file:

| Stage | When | What it measures |
| --- | --- | --- |
| **Existing tests** (`baseline`) | Always, when a test file exists. Mutation-tested only with `--baseline` or `--no-generate`. | The tests you already had. |
| **Generated tests** (`generated`) | Unless `--no-generate`. | The model's first proposal, after validation. |
| **Improved tests** (`improved`) | Once per improvement round. With more than one round the label is `Improved tests (round N)`. | A proposal that targets the previous stage's undetected mutants. |

A proposal that still fails validation after `max_repairs` retries is recorded as a **rejected** stage with its problems. Rejected stages are shown in the report but never kept.

## Mutation score

Stryker changes the source file in small ways, one mutant at a time, and runs the selected test file against each change.

| Status | Counts as | Meaning |
| --- | --- | --- |
| Killed | detected | A test failed with the mutant applied. |
| Timeout | detected | The tests ran too long with the mutant applied, which usually means an infinite loop was introduced. |
| Survived | undetected | Tests covered the mutated code, but all passed. |
| No coverage | undetected | No test ran the mutated code. |
| Compile or runtime error | excluded | The mutant could not run at all. |
| Ignored or pending | excluded | Not included in the numerator or the denominator. |

```text
score = (killed + timeout) / (killed + timeout + survived + no coverage) × 100
```

In `regress run` and `regress report`, the **Killed** figure is `killed + timeout`. The web app and `report.json` keep those counts separate. The formula uses the separate counts.

Only the selected source file is mutated, and only the selected test file runs. The score describes how well that one test file pins down that one source file. It is not coverage for the whole project, and a high score does not prove the implementation is correct.

When the model claims a mutant is equivalent (it cannot change behaviour), the report lists the claim, but the mutant still counts in the score.

## Which tests are kept

- **Generated tests** replace the existing tests when they pass validation, even if the existing tests scored higher. A measured baseline is shown for comparison only.
- An **improvement** replaces the current tests when its score is equal to or higher than the current score. A lower-scoring improvement is recorded, and the previous version stays.
- With `--no-generate`, the existing tests are the starting point, and improvements are compared against them.

The report's `kept_stage` names the stage whose test file is left in your project. The **change** shown in the CLI, the Runs table, and the run page is the kept score minus the score of the generated tests, or of the existing tests with `--no-generate`.

If a run fails or is cancelled, Regress restores the original source and test file. The artifacts stay in the run directory for diagnosis.

## Report fields

`report.json` is the serialized run. The main fields:

| Field | Meaning |
| --- | --- |
| `id`, `created_at` | Run ID and start time with time zone. |
| `source_file`, `test_file`, `test_file_existed` | Files relative to `project_root`, and whether the test file existed before the run. |
| `model` | Model used for the run. |
| `mutate_lines` | The source lines Stryker mutated, as `[start, end]` pairs (1-based, inclusive), in a `--changed` run. Empty when it mutated the whole file. |
| `batch_id` | The multi-file run this run belongs to, if any. |
| `status`, `error` | `running`, `completed`, `failed`, or `cancelled`, and the error message if any. |
| `stages[]` | Each stage's `kind`, `label`, `test_count`, `test_names`, `mutation` results, model `summary`, `attempts`, `llm_seconds`, `targeted_mutants`, `equivalent_mutants`, `rejected`, and `problems`. |
| `stages[].mutation` | The Stryker run: `mutants[]` with status, operator, location, and covering tests, plus `killed`, `survived`, `no_coverage`, `timeout`, `errors`, and `score`. |
| `kept_stage` | Label of the kept stage. |
| `usage` | Model `calls`, `input_tokens` (including `cached_input_tokens`), and `output_tokens` for the whole run. |
| `cost_usd`, `price` | What the model calls cost in USD, and the price (USD per million tokens) it was computed with. Null when the model's price isn't known. See [Costs and budgets](/docs/reference/costs). |
| `max_cost`, `stop_reason` | The run's budget, and why it stopped before its last round, for example because the next call would have gone past the budget. |
| `duration_seconds` | Wall-clock time of the finished run. |

`events.jsonl` has one JSON object per line with `seq`, `time`, `type`, `message`, and `data`. It is the log the web app shows while a run is live, and the source of [`GET /api/runs/{id}/events`](/docs/reference/http-api#follow-a-run).

## Multi-file runs

A run over several files (`regress run src/`, `regress run --changed main`) saves each file's run as above, plus a summary at `.regress/batches/<id>.json`, where the ID is a timestamp followed by `batch`. It is saved after each file, so it shows how far an interrupted run got.

| Field | Meaning |
| --- | --- |
| `id`, `created_at`, `project_root`, `model` | As in a run report. |
| `changed_since` | The ref given to `--changed`, if any. |
| `status` | `completed` when every file completed or was skipped, `failed` when any file failed, `cancelled` when interrupted. |
| `files[]` | One entry per file, in run order. |
| `files[].source_file`, `files[].run_id` | The file, and its run directory under `.regress/runs/` (none for a skipped file). |
| `files[].status`, `files[].error` | `completed`, `failed`, `skipped`, `cancelled`, or `pending` (not reached), and why it failed or was skipped. |
| `files[].mutate_lines` | The lines mutated; empty for the whole file. |
| `files[].tests_first`, `files[].tests_kept`, `files[].score_first`, `files[].score_kept` | Test counts and scores of the first measured stage and of the kept one. |
| `files[].detected_first`, `files[].detected_kept`, `files[].valid_mutants` | Mutant counts behind the combined score. |
| `files[].cost_usd` | What the file's run cost, when its price is known. |
| `duration_seconds` | Wall-clock time of the whole run. |

## Checks

`regress check` saves `.regress/checks/<id>/check.json`, where the ID is a timestamp followed by `check`, with each file's Vitest and Stryker artifacts in numbered subdirectories (`01/vitest/`, `01/stryker/`).

| Field | Meaning |
| --- | --- |
| `id`, `created_at`, `project_root`, `changed_since` | As in a multi-file run. |
| `fail_under` | The threshold, if any. |
| `files[].source_file`, `files[].test_file`, `files[].mutate_lines` | The file, its test file, and the lines mutated (empty for the whole file). |
| `files[].status`, `files[].error` | `scored`, `no-tests`, `skipped`, `failed`, or `pending` (not reached), and the reason. |
| `files[].tests`, `files[].killed`, `files[].timeout`, `files[].survived`, `files[].no_coverage`, `files[].score` | The test count, the mutant counts, and the score. |
| `files[].survivors[]` | Undetected mutants spread across the file: `id`, `mutator`, `status`, `line`, and the `original` and `mutated` line. |
| `duration_seconds` | Wall-clock time of the check. |

## Delete old runs

Artifacts are kept until you remove them. Delete a finished run's directory, or call `DELETE /api/runs/{id}` on a running API. Deleting a run does not touch the test file in your project.
